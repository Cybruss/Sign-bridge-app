# Text-to-sign scope and integration assessment

## Current app behavior

The home-screen local “Text to Sign · word demo” route opens `AvatarPipelineScreen`. It normalizes the replacement Amy GLB's animation names into a word/phrase lookup (about 2,007 unique names) and plays matched clips in order, preferring longer phrase clips where available. It reports words with no clip. This verifies clip lookup/playback only; it does not establish sign-language correctness or translate English into ASL grammar. The avatar asset and its provenance are described in [AVATAR_SETUP.md](AVATAR_SETUP.md).

An additional `TextToSignScreen` parses three SiGML samples (`welkom-ngt`, `iTakeMug`, `scotland-H`) and assembles matching gloss blocks. The screen is now reachable from Home, and `pubspec.yaml` bundles a small CWASA subset, one avatar, and the sample lexicon. This path is an experimental example player: the source examples are NGT, coverage is limited, and joining gloss blocks is not English grammar translation or ASL. The JAS bundle includes mixed licenses, including CC BY-NC-ND content and GPL code; inspect before redistribution or modification.

## Sign.mt/Rylo Translate online fallback

Sign Bridge now has a separate **Rylo Translate · online** home action. It opens the official hosted text-to-sign interface in an in-app HTTPS WebView. No upstream source code, assets, private API, or model weights are bundled or copied. The user enters text directly into Rylo's page; the app displays a notice that text is sent to the service and that service availability controls its output. A retry and main-frame load error are visible.

The official [sign/translate repository](https://github.com/sign/translate) describes spoken-text-to-sign production through normalized text, SignWriting, pose sequence generation, and skeleton/3D avatar rendering. It is a substantial Ionic/Angular application with a separately hosted translation service, not a drop-in Flutter library or a documented public API. The current public interface and current upstream source explicitly say the latest Sign models are in research preview and not available to the public. Therefore, the in-app route is an online fallback entry point, not proof that translation generation is currently available or produces a sign video.

The upstream repository's license describes free CC BY-NC-SA 4.0 use for individuals, non-profit organizations, and educational institutions; a commercial license is separately required. Do not repackage upstream source or assets without retaining attribution and following the share-alike/non-commercial terms. Model weights, datasets, hosted services, and other assets may have separate requirements. See [DATASET_AND_LICENSES.md](DATASET_AND_LICENSES.md).

## Honest supported scope

- Full-sentence ASL translation: **not implemented**.
- Embedded Rylo Translate web route: **implemented; live translation generation not available/verified**.
- Verified ASL sign video or pose generation generated by Rylo in this app: **not verified**.
- Existing small GLB glossary/animation prototype: **present, unverified sign motion**.
- Updated Amy GLB clip dictionary: **about 2,007 normalized clip names; one animation per recognized word/phrase where available; English syntax and sign correctness are not validated**.
- Existing SiGML example parser/player path: **reachable partial prototype; NGT examples, narrow coverage, and licensing review still needed**.
- On-device online page load, network behavior, language availability, and genuine generated output: **must be tested on the connected Pixel**.

The safe product label for the local home action is “Text to Sign · word demo.” Do not describe this animation lookup as unrestricted translation. A future adapter must identify source and target language (for example English→ASL), surface unsupported words, retain the original text, cancel/handle failures, and play actual generated signs.
